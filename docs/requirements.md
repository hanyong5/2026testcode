# Todo List 기능 요구사항

관련 Issue: [#5](https://github.com/hanyong5/2026testcode/issues/5)

## 목적과 적용 범위

HTML5, CSS3, Vanilla JavaScript, LocalStorage로 구현할 단일 사용자 Todo List의
필수 기능과 검증 가능한 수용 기준을 정의합니다.
이 문서는 요구사항 산출물이며 아래 기능이 현재 구현되었다는 의미는 아닙니다.
정책은 이 PR의 제안 기준이며 리뷰·병합 후 구현 기준으로 사용합니다.

필수 범위:

- 텍스트 Todo의 등록·조회·수정·삭제
- 항목별 완료 상태 전환과 전체·진행 중·완료 필터
- 입력 검증, 빈 목록 및 오류 안내
- 같은 브라우저·동일 출처에서 LocalStorage 저장·복원

제외 범위:

- 로그인, 서버 API, 외부 서비스 및 기기 간 동기화
- 다중 탭 간 실시간 동기화와 동시 편집 충돌 해결
- 마감일, 우선순위, 태그, 검색, 정렬 변경 및 드래그 앤 드롭
- 일괄 삭제, 삭제 취소, 휴지통, 데이터 가져오기·내보내기
- UI 와이어프레임·화면 흐름의 상세 설계(#6, #8)와 저장 키·JSON 스키마 상세 설계(#7)
- 이 Issue에서의 기능 코드 구현 및 실행 테스트 케이스 전체 작성(#14)

## 공통 정책

| 항목 | 기준 |
|---|---|
| Todo 내용 | 앞뒤 공백을 제거한 한 줄 텍스트, 1~200자. 길이는 유니코드 코드포인트 기준 |
| 중복 내용 | 허용. 내용이 같아도 항목을 각각 식별·수정·삭제할 수 있어야 함 |
| 초기 완료 상태 | 미완료 |
| 목록 순서 | 새로 등록한 항목이 위에 표시됨. 수정·완료 전환으로 순서가 바뀌지 않음 |
| 최초 선택 필터 | 전체. 필터 선택과 편집 중 초안은 저장 대상이 아님 |
| 저장 대상 | Todo 식별 정보, 정규화된 내용, 완료 상태 및 목록 순서 |
| 사용 환경 | 최신 안정 버전 Chrome·Edge·Firefox·Safari의 단일 탭, 동일 출처 기준 |
| 오류 안내 | 원인을 읽을 수 있는 텍스트로 표시. 콘솔 메시지만으로 알리지 않음 |

## 1. Todo 등록·조회·수정·삭제

### FR-01. Todo 등록

유효한 내용을 제출하면 기존 항목과 구분되는 Todo를 생성합니다.

수용 기준:

- 유효한 내용을 입력하고 등록 버튼 또는 입력란에서 Enter를 누르면 항목이 정확히 1개 추가됩니다.
- 새 항목은 앞뒤 공백이 제거되고 미완료 상태로 목록 맨 위에 표시됩니다.
- 등록 성공 후 입력란이 비워지며, 같은 내용을 다시 등록해도 서로 독립된 항목으로 표시됩니다.
- 진행 중 필터에서는 새 항목이 보이고 완료 필터에서는 보이지 않습니다. 필터 선택은 유지됩니다.
- 유효하지 않은 입력은 FR-07에 따라 처리하며 기존 Todo는 변경하지 않습니다.

### FR-02. Todo 조회

저장된 Todo를 복원한 뒤 현재 선택한 필터에 해당하는 목록을 표시합니다.

수용 기준:

- 초기 진입 시 전체 필터가 선택되고 각 항목의 내용과 완료 여부가 표시됩니다.
- 화면에 표시되는 각 항목은 내부 데이터의 해당 항목과 내용·완료 상태가 일치합니다.
- 등록 순서가 서로 다른 항목을 등록·복원해도 최신 등록 항목부터 동일한 순서로 표시됩니다.
- 조회 또는 필터 변경만으로 Todo의 내용·개수·완료 상태를 변경하지 않습니다.
- 표시할 항목이 없으면 FR-08의 빈 상태 안내를 표시합니다.

### FR-03. Todo 수정

선택한 Todo의 내용을 변경하며 완료 상태와 목록 순서는 유지합니다.

수용 기준:

- 항목의 수정 동작을 선택하면 기존 내용을 편집할 수 있습니다.
- 유효한 내용으로 저장하면 대상 항목만 갱신되고 식별 정보·완료 상태·위치는 유지됩니다.
- 취소 버튼 또는 Escape로 취소하면 기존 내용으로 돌아가며 저장소를 변경하지 않습니다.
- 비어 있거나 제한을 넘긴 수정 내용은 저장되지 않습니다. 오류를 안내하고 편집 내용을 유지해 다시 입력할 수 있습니다.
- 중복 내용이 있거나 필터가 적용되어 있어도 선택한 항목만 수정됩니다.

### FR-04. Todo 삭제

선택한 항목을 목록과 데이터에서 즉시 제거합니다. 삭제 취소는 제공하지 않습니다.

수용 기준:

- 삭제 버튼을 누르면 선택한 항목만 제거되고 다른 항목의 내용·상태·순서는 유지됩니다.
- 중복 내용이 있거나 필터가 적용되어 있어도 대상 항목만 삭제됩니다.
- 삭제 후 현재 필터에 보일 항목이 없으면 해당 필터의 빈 상태를 표시합니다.
- 정상 저장 가능한 환경에서는 새로고침 후에도 삭제한 항목이 다시 나타나지 않습니다.

## 2. 완료 상태와 필터

### FR-05. 완료 상태 전환

각 항목의 미완료·완료 상태를 양방향으로 전환합니다.

수용 기준:

- 미완료 항목의 완료 컨트롤을 조작하면 완료가 되고, 다시 조작하면 미완료가 됩니다.
- 대상 항목의 완료 상태만 바뀌며 내용과 목록 순서는 유지됩니다.
- 완료 여부를 체크 상태와 화면 표시로 구분할 수 있고 키보드로도 전환할 수 있습니다.
- 진행 중 필터에서 완료로 바꾼 항목과 완료 필터에서 미완료로 바꾼 항목은 현재 목록에서 즉시 사라집니다.
- 정상 저장 가능한 환경에서는 새로고침 후에도 변경한 완료 상태가 유지됩니다.

### FR-06. 전체·진행 중·완료 필터

필터는 저장된 원본 데이터를 바꾸지 않고 표시할 항목만 선택합니다.

수용 기준:

- 완료 1개와 미완료 2개가 있으면 전체에는 3개, 진행 중에는 미완료 2개, 완료에는 완료 1개가 표시됩니다.
- 현재 선택한 필터가 화면에서 식별되고 키보드로 필터를 선택할 수 있습니다.
- 필터 변경·등록·수정·삭제·완료 전환 후 표시 결과는 현재 데이터와 필터 조건에 일치합니다.
- 필터 전환으로 숨겨진 Todo를 삭제하거나 저장 데이터에서 누락시키지 않습니다.
- 새로고침 시 필터는 전체로 돌아가며 Todo 데이터 자체는 유지됩니다.

## 3. 입력 검증·빈 목록·LocalStorage

### FR-07. 입력 검증과 텍스트 처리

등록과 수정에 같은 입력 정책을 적용하고 사용자 내용을 텍스트로 취급합니다.

수용 기준:

- 빈 문자열과 공백만 있는 내용을 제출하면 오류 안내가 표시되고 데이터는 변경되지 않습니다.
- 앞뒤 공백 제거 후 1자와 200자는 허용하고 201자는 거부합니다. 거부 시 자동으로 잘라 저장하지 않습니다.
- 내용 중 줄바꿈이 있으면 한 줄 입력 안내와 함께 거부하며 기존 데이터는 유지됩니다.
- `<script>alert(1)</script>` 같은 문자열은 허용 길이 안에서 문자 그대로 표시되며 HTML이나 스크립트로 실행되지 않습니다.
- 잘못된 입력을 거부한 경우 입력 내용과 오류 안내를 유지하고, 유효한 내용으로 성공하면 해당 오류 안내를 해제합니다.

### FR-08. 빈 목록 안내

Todo가 아예 없는 상태와 현재 필터에 결과가 없는 상태를 구분해 안내합니다.

수용 기준:

- 최초 방문 또는 마지막 Todo 삭제 후 전체 목록이 비어 있으면 Todo 등록을 안내합니다.
- 데이터가 있어도 현재 필터에 해당하는 항목이 없으면 해당 상태의 Todo가 없음을 안내합니다.
- 빈 결과 상태에서도 입력란과 필터를 사용할 수 있으며 데이터 오류로 처리하지 않습니다.
- 유효한 Todo를 추가하거나 필터를 바꾸어 결과가 생기면 빈 상태 안내가 사라집니다.

### FR-09. LocalStorage 저장·복원

정상 저장 가능한 환경에서 Todo 변경을 지속시키고 같은 출처로 재방문하면 복원합니다.
저장 키·스키마·데이터 유효성 판정의 상세 내용은 Issue #7에서 정합니다.

수용 기준:

- 등록·수정·삭제·완료 전환이 성공하면 변경 결과 전체를 저장합니다. 필터에 보이지 않는 항목도 포함합니다.
- 같은 출처에서 새로고침 또는 브라우저 재방문 시 마지막 저장에 성공한 내용·완료 상태·목록 순서가 복원됩니다.
- 앱의 저장 항목이 없으면 정상적인 빈 목록으로 시작하고 오류로 표시하지 않습니다.
- 필터 선택과 저장 전 편집 초안은 복원하지 않습니다.
- 다른 앱이 사용하는 LocalStorage 항목을 수정하거나 삭제하지 않습니다.

### FR-10. 저장소 오류와 데이터 보호

읽기·쓰기 실패, 손상된 JSON 및 호환되지 않는 데이터로 앱이 중단되지 않게 합니다.

수용 기준:

- 저장소 접근 제한으로 읽기에 실패하면 오류를 안내하고 메모리상의 Todo 작업을 사용할 수 있습니다. 저장·복원이 보장되지 않음을 표시합니다.
- 쓰기에 실패하면 현재 화면의 변경은 유지하고 저장 실패를 안내합니다. 저장 성공으로 표시하지 않으며 다음 변경 시 저장을 재시도합니다.
- 쓰기 실패 후 새로고침하면 마지막 저장에 성공한 상태만 복원될 수 있음을 사용자에게 알립니다.
- JSON 파싱 또는 데이터 형식 검증에 실패하면 복원 오류를 안내하고 빈 메모리 목록으로 시작합니다. 원본 저장 값은 유지하며 자동 덮어쓰기를 차단합니다.
- 손상 데이터로 자동 저장이 차단된 경우 사용자에게 앱 데이터 초기화 선택을 제공합니다. 명시적으로 동의하기 전에는 저장 값을 변경하지 않습니다.
- 초기화에 동의하면 앱 전용 저장 항목만 초기화하고, 현재 메모리 목록의 저장 성공을 확인한 후 저장 가능 상태로 전환합니다. 실패하면 오류 상태를 유지합니다.
- 오류가 발생해도 원시 저장 데이터나 인증 정보가 화면에 노출되지 않습니다.
