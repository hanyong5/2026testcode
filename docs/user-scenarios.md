# 사용자 시나리오 및 화면 흐름

관련 Issue: [#6](https://github.com/hanyong5/2026testcode/issues/6)

기준 문서: [Todo List 기능 요구사항](requirements.md)

## 목적과 범위

Todo List의 사용자 동작, 화면 상태 전환과 피드백을 정의합니다.
HTML5·CSS3·Vanilla JavaScript·LocalStorage 기반 단일 사용자·단일 탭 환경을 전제로 합니다.
기존 FR-01~FR-10 정책을 기준으로 작성한 초안이며, 새로 필요한 정책은 미확정 사항으로 구분합니다.
시나리오를 문서화한 것이며 기능 구현이나 브라우저 테스트 완료를 의미하지 않습니다.

이 문서의 범위는 최초 방문·CRUD·완료 전환·필터·재방문과 입력·저장소 오류 흐름입니다.
화면 배치와 시각 디자인은 Issue #8~#10, 저장 키와 데이터 스키마는 #7,
기능 구현과 실행 테스트는 #11~#15에서 구체화합니다.
안내 문구는 예시이며 동일한 의미를 전달하는 표현으로 조정할 수 있습니다.

## 기존 정책

- Todo는 앞뒤 공백 제거 후 한 줄 텍스트 1~200자이며, 길이는 유니코드 코드포인트 기준입니다.
- 중복 내용은 허용하고 각 항목을 독립적으로 수정·삭제합니다.
- 새 Todo는 미완료 상태로 목록 맨 위에 표시하며 수정·완료 전환으로 순서를 바꾸지 않습니다.
- 최초 진입과 재방문의 필터는 전체입니다. 필터 선택과 편집 초안은 저장하지 않습니다.
- 작업 중에는 선택한 필터를 유지합니다. 필터에 숨겨진 항목도 데이터와 저장 대상에 포함합니다.
- 삭제는 즉시 적용하고 삭제 취소는 제공하지 않습니다.
- 오류 안내는 화면에서 읽을 수 있어야 하며, 저장 실패와 저장 성공을 구분합니다.

## 화면 상태 표현

아래 상태명은 시나리오 설명용이며 구현 코드의 구조를 지정하지 않습니다.
필터, 목록, 편집·입력, 저장 상태를 함께 표현해 서로 다른 상황이 섞이지 않도록 합니다.

| 구분 | 상태 | 사용자에게 보이는 결과 |
|---|---|---|
| 목록 | 전체 데이터 없음 | Todo 등록을 안내하는 빈 목록 |
| 목록 | 선택 필터의 결과 있음 | 조건에 맞는 항목과 각 완료 상태 |
| 목록 | 전체 데이터는 있으나 필터 결과 없음 | 현재 필터에 해당하는 Todo가 없다는 안내 |
| 편집·입력 | 일반 조회 | 등록·수정 시작·삭제·완료 전환·필터 선택 가능 |
| 편집·입력 | 항목 편집 | 기존 내용이 채워진 편집 영역과 저장·취소 동작 |
| 편집·입력 | 입력 오류 | 입력 내용을 유지하고 해당 입력과 연결된 오류 안내 |
| 저장 | 정상 복원·변경 없음 또는 저장 성공 | 메모리와 마지막 저장 성공 상태가 일치함. 최초 빈 상태는 저장 성공으로 오인시키지 않음 |
| 저장 | 쓰기 실패·미저장 변경 있음 | 현재 변경이 화면에 남고 저장 실패·새로고침 시 유실 가능성 안내 |
| 저장 | 읽기 실패 | 복원 실패 및 현재 작업의 지속성이 보장되지 않는다는 안내 |
| 저장 | 손상 데이터 보호 | 원본 저장 값을 보존하고 자동 덮어쓰기를 차단하며 초기화 선택 안내 |

입력 오류·저장 오류와 빈 목록은 동시에 나타날 수 있습니다.
오류가 있다는 이유로 정상적인 빈 목록 안내나 입력·필터 동작을 숨기지 않습니다.

## 1. 최초 방문·등록·수정·삭제

### US-01. 최초 방문

- 관련 요구사항: FR-02, FR-08, FR-09
- 사전 조건: 앱 전용 저장 항목이 없으며 저장소 읽기는 가능합니다.
- 사용자 동작: 앱을 엽니다.
- 화면 전환: 초기 진입 → 저장 항목 없음 확인 → 전체 필터·전체 데이터 없음 상태.
- 피드백: 예를 들어 “등록된 할 일이 없습니다. 할 일을 추가해 보세요.”를 표시합니다. 오류로 안내하지 않습니다.
- 종료 조건: 입력란과 필터를 사용할 수 있고 Todo를 등록할 수 있습니다.

### US-02. Todo 등록

- 관련 요구사항: FR-01, FR-06, FR-07, FR-09
- 사전 조건: 입력란을 사용할 수 있으며 저장 가능한 정상 환경입니다.
- 사용자 동작: 유효한 내용을 입력하고 등록 버튼 또는 입력란의 Enter로 제출합니다.
- 화면 전환: 입력 → 검증 통과 → 미완료 항목 1개 추가·저장 → 현재 필터로 목록 갱신.
- 피드백: 입력란을 비웁니다. 전체·진행 중 필터에서는 새 항목을 목록 맨 위에 표시합니다.
- 완료 필터에서는 새 항목이 보이지 않으므로 “진행 중 할 일이 등록되었습니다.” 같은 성공 안내를 제안합니다. 필터를 자동 변경하지 않습니다.
- 종료 조건: 독립된 항목이 정확히 1개 생기고 저장에 성공합니다. 중복 내용도 별도 항목으로 등록됩니다.
- 예외 분기: 입력 오류는 US-08, 저장 실패는 US-10으로 연결합니다.

### US-03. Todo 수정·취소

- 관련 요구사항: FR-03, FR-07, FR-09
- 사전 조건: 현재 목록에 수정할 항목이 표시되어 있습니다.
- 사용자 동작: 대상 항목의 수정 동작을 선택해 내용을 편집합니다.
- 화면 전환: 일반 조회 → 기존 내용을 채운 편집 상태 → 유효한 내용 저장 → 일반 조회.
- 피드백: 저장 후 대상 내용만 갱신하며 식별 정보·완료 상태·목록 순서는 유지합니다.
- 취소 분기: 취소 버튼 또는 Escape → 기존 내용으로 일반 조회 복귀. 저장 데이터는 변경하지 않습니다.
- 종료 조건: 중복 내용이나 필터 적용 여부와 관계없이 선택한 항목만 수정됩니다.
- 예외 분기: 잘못된 수정 내용은 편집 상태와 초안을 유지하고 US-08로 연결합니다. 저장 실패는 US-10으로 연결합니다.
- 미확정 사항: 편집 중 필터 변경·다른 항목 편집·대상 삭제의 처리 정책은 D-01에서 검토합니다.

### US-04. Todo 삭제

- 관련 요구사항: FR-04, FR-08, FR-09
- 사전 조건: 현재 목록에 삭제할 항목이 표시되어 있고 저장 가능한 정상 환경입니다.
- 사용자 동작: 대상 항목의 삭제 버튼을 누릅니다.
- 화면 전환: 항목 표시 → 대상 항목 제거·저장 → 현재 필터로 목록 갱신.
- 피드백: 남은 결과가 있으면 목록을 표시합니다. 전체 데이터가 없으면 최초 빈 목록 안내를, 숨겨진 데이터만 남으면 필터 결과 없음 안내를 표시합니다.
- 종료 조건: 대상만 삭제되고 다른 항목의 내용·상태·순서가 유지되며 재방문해도 삭제한 항목이 복원되지 않습니다.
- 예외 분기: 저장 실패는 US-10으로 연결합니다. 삭제 후 키보드 포커스 위치는 D-03에서 검토합니다.

## 2. 완료 전환·필터·재방문

### US-05. 완료 상태 전환

- 관련 요구사항: FR-05, FR-06, FR-08, FR-09
- 사전 조건: 대상 Todo가 화면에 표시되어 있습니다.
- 사용자 동작: 마우스 또는 키보드로 항목의 완료 컨트롤을 조작합니다.
- 화면 전환: 미완료 ↔ 완료 → 현재 필터 결과 재계산·저장.
- 피드백: 전체 필터에서는 항목의 위치와 내용은 유지하고 완료 표시만 바꿉니다.
- 진행 중 필터에서 완료로, 완료 필터에서 미완료로 바꾸면 대상이 현재 목록에서 사라집니다. 결과가 없으면 US-09로 연결합니다.
- 종료 조건: 대상 상태만 바뀌고 정상 저장 시 재방문 후에도 해당 상태가 유지됩니다.
- 예외 분기: 저장 실패는 US-10으로 연결합니다. 항목이 숨겨진 뒤 포커스 위치는 D-03에서 검토합니다.

### US-06. 필터 변경

- 관련 요구사항: FR-06, FR-08
- 사전 조건: 편집 중 초안이 없는 일반 조회 상태이며 완료 1개·미완료 2개가 있습니다.
- 사용자 동작: 전체·진행 중·완료 필터를 선택합니다.
- 화면 전환: 기존 필터 → 새 필터 선택 표시 → 해당 조건으로 목록 갱신.
- 피드백: 전체 3개·진행 중 2개·완료 1개가 각각 표시됩니다. 결과가 없으면 US-09로 연결합니다.
- 종료 조건: 데이터의 내용·개수·완료 상태·순서를 변경하지 않고 표시 대상만 달라집니다.
- 미확정 사항: 편집 초안이 있을 때의 전환은 D-01에서 검토합니다.

### US-07. 새로고침·재방문

- 관련 요구사항: FR-02, FR-06, FR-09
- 사전 조건: 같은 브라우저·동일 출처에 유효한 저장 데이터가 있습니다.
- 사용자 동작: 새로고침하거나 앱을 다시 엽니다.
- 화면 전환: 초기 진입 → 데이터 복원 → 전체 필터·복원한 목록 표시.
- 피드백: 마지막 저장에 성공한 내용·완료 상태·목록 순서를 표시합니다. 이전 필터와 편집 초안은 복원하지 않습니다.
- 종료 조건: 마지막 저장 성공 상태와 화면이 일치합니다. 저장 실패 이후의 메모리 변경은 복원을 보장하지 않습니다.
- 예외 분기: 데이터 없음은 US-01, 읽기 실패는 US-11, 손상 데이터는 US-12로 연결합니다.

## 3. 빈 목록·입력 오류·저장소 오류

### US-08. 잘못된 입력

- 관련 요구사항: FR-03, FR-07
- 사전 조건: 등록 또는 수정 내용을 입력할 수 있습니다.
- 사용자 동작: 빈 문자열·공백만 있는 내용·201자 이상·줄바꿈이 포함된 내용을 제출합니다.
- 화면 전환: 등록 입력 또는 항목 편집 → 입력 오류 → 내용 수정·재제출 → 정상 동작.
- 피드백: “할 일을 입력하세요”, “200자 이내의 한 줄로 입력하세요”처럼 원인을 안내하고 입력 내용은 유지합니다. 초과 내용을 자동으로 잘라 저장하지 않습니다.
- 종료 조건: 거부된 입력은 Todo와 저장 데이터를 변경하지 않습니다. 유효한 제출이 성공하면 해당 입력 오류 안내가 해제됩니다.
- 경계 조건: 앞뒤 공백 제거 후 1자·200자는 허용합니다. 길이 내 HTML 형태의 문자열은 텍스트로 표시하며 실행하지 않습니다.
- 예외 분기: 검증을 통과했으나 저장이 실패하면 입력 오류와 구분해 US-10을 적용합니다.

### US-09. 필터 결과 없음

- 관련 요구사항: FR-06, FR-08
- 사전 조건: Todo 데이터는 있지만 현재 필터에 맞는 항목이 없습니다.
- 사용자 동작: 필터 변경, 삭제 또는 완료 전환으로 표시할 항목이 없어집니다.
- 화면 전환: 목록 표시 → 필터 결과 없음. 전체 데이터까지 사라졌다면 전체 데이터 없음 상태로 전환합니다.
- 피드백: “완료된 할 일이 없습니다”처럼 현재 조건에 맞춘 문구를 표시합니다. 데이터 오류로 안내하지 않습니다.
- 종료 조건: 등록과 필터 선택을 계속 사용할 수 있고, 조건에 맞는 결과가 생기면 빈 상태 안내가 사라집니다.

### US-10. 저장 실패

- 관련 요구사항: FR-09, FR-10
- 사전 조건: 데이터를 정상 복원했거나 저장 항목이 없음을 확인했으며, Todo 변경 후 저장소 쓰기에 실패합니다.
- 사용자 동작: 등록·수정·삭제·완료 전환을 수행합니다.
- 화면 전환: 변경을 화면에 반영 → 쓰기 실패 → 현재 목록 유지·미저장 상태 표시.
- 피드백: “변경 내용을 저장하지 못했습니다. 새로고침하면 마지막 저장 상태로 돌아갈 수 있습니다.”처럼 실패와 유실 가능성을 알립니다.
- 복구 흐름: 다음 Todo 변경 시 저장 재시도 → 전체 메모리 데이터 저장 성공 → 미저장 오류 안내 해제.
- 종료 조건: 실패한 저장을 성공으로 표시하지 않습니다. 반복 실패 시 현재 메모리 작업과 오류 안내를 유지합니다.
- 구분: 손상 데이터로 자동 덮어쓰기가 차단된 US-12에는 이 자동 재시도 흐름을 적용하지 않습니다.

### US-11. 저장소 읽기 실패

- 관련 요구사항: FR-10
- 사전 조건: 저장소 접근 제한 등으로 기존 데이터 읽기에 실패합니다.
- 사용자 동작: 앱을 엽니다.
- 화면 전환: 초기 진입 → 복원 실패 안내·빈 메모리 목록으로 진입.
- 피드백: 복원 실패와 현재 작업의 저장·복원이 보장되지 않음을 안내합니다. 데이터가 없음을 정상 확인한 US-01과 구분합니다.
- 종료 조건: 메모리상의 Todo 작업을 사용할 수 있고 기존 내용을 복원했다고 표시하지 않습니다.
- 미확정 사항: 읽기 실패 후 자동 저장을 언제 재개할지는 D-02에서 검토합니다. 정상 복원 전 기존 데이터를 덮어쓰는 흐름을 확정하지 않습니다.

### US-12. 손상 데이터·초기화 선택

- 관련 요구사항: FR-10
- 사전 조건: 저장 값은 읽었지만 JSON 파싱 또는 데이터 형식 검증에 실패합니다.
- 사용자 동작: 앱을 열고 복원 오류 안내를 확인합니다.
- 화면 전환: 초기 진입 → 빈 메모리 목록·손상 데이터 보호 → 초기화 선택 안내.
- 피드백: 원본 저장 값을 유지하고 자동 덮어쓰기를 차단합니다. 원시 저장 데이터나 인증 정보를 노출하지 않습니다.
- 동의하지 않는 흐름: 보호 상태와 메모리상의 작업을 유지하며 원본 저장 값을 변경하지 않습니다.
- 명시적 동의 흐름: 앱 전용 저장 항목 초기화 → 현재 메모리 목록 저장 → 성공하면 정상 저장 상태로 전환. 다른 앱의 저장 항목은 유지합니다.
- 종료 조건: 동의 전 원본이 보존됩니다. 초기화·저장 실패 시 오류 상태를 유지하고 성공으로 표시하지 않습니다.

## 미확정 정책과 제안

아래 제안은 기존 요구사항의 확정 정책에 추가되는 사항이며 리뷰에서 결정해야 합니다.

| ID | 확인할 사항 | 제안 | 영향 |
|---|---|---|---|
| D-01 | 편집 중 필터 이동·다른 항목 편집·편집 대상 삭제 | 한 번에 한 항목만 편집하고, 초안이 있으면 저장·취소를 명시적으로 선택한 뒤 다른 동작 수행 | 초안 유실 방지 및 화면 전환 조건 |
| D-02 | 읽기 실패 후 저장 재개 조건 | 기존 데이터 읽기에 성공하고 복원·처리 방침을 확인하기 전에는 메모리 전용 작업으로 유지 | 미복원 데이터의 자동 덮어쓰기 방지. #7·#13과 정책 합의 필요 |
| D-03 | 삭제·완료 전환으로 항목이 사라진 후 키보드 포커스 | 다음 표시 항목, 없으면 이전 항목, 목록이 비었으면 등록 입력란으로 이동 | 키보드 사용자의 연속 작업 |

제안 정책이 기존 FR의 동작을 바꾸는 경우 기준 요구사항도 함께 검토·갱신해야 합니다.
특히 D-02는 저장소 접근이 회복되었을 때의 데이터 보호 조건이므로 구현 전에 확정합니다.
