# Requirements Analysis

이 저장소의 요구사항을 기존 정책과 연결하고 검증 가능한 문서로 정리합니다.
기본 산출물 언어는 한국어이며 사용자가 지정한 언어·형식·경로가 있으면 따릅니다.

## 기준 자료

- 먼저 저장소 루트의 AGENTS.md와 작업 경로에 적용되는 추가 지침을 읽습니다. Git·Issue·PR 절차는 해당 지침을 따릅니다.
- Issue가 지정되면 GitHub MCP로 본문·체크리스트·관련 PR을 확인합니다. 검토 대상 문서와 구현 상태를 함께 살펴 중복 작업을 피합니다.
- README.md와 docs/requirements.md가 있으면 기존 범위·정책·요구사항 ID를 기준으로 사용합니다. 로컬에 문서가 없을 때는 현재 브랜치와 원격 반영 여부를 확인한 뒤 새로 작성할지 판단합니다.
- 이 프로젝트는 HTML5·CSS3·Vanilla JavaScript·LocalStorage 기반입니다. 요청 없이 서버·로그인·프레임워크를 요구사항에 추가하지 않습니다.

## 분석 및 문서화

1. 요청이 분석만인지 문서 작성·수정까지인지 구분합니다. 분석 요청만으로 파일 작성, Issue 변경 또는 구현을 시작하지 않습니다.
2. 요청한 체크리스트를 기존 문서에 대조해 충족 항목·누락·충돌을 구분합니다. 확정 요구사항, 제안 정책·가정, 미해결 질문을 분리하고 근거 문서나 Issue를 표시합니다.
3. 기능과 관찰 가능한 결과를 먼저 정의합니다. 범위에 영향을 주는 불명확한 조건은 질문하고, 진행을 막지 않는 세부 정책은 제안으로 표시합니다. 기존에 승인된 제한값과 동작을 임의로 바꾸지 않습니다.
4. 요구사항별 수용 기준을 작성합니다. 적절한 사전 조건, 사용자 동작, 기대 결과를 포함하고 관련 있는 정상·경계·실패 상황을 구체화합니다. 모호한 표현을 쓰는 대신 개수·상태·유지되어야 할 데이터 등으로 판단 가능하게 만듭니다.
5. 문서 작성이 요청되면 기존 산출물을 우선 갱신합니다. 새 요구사항 문서의 기본 경로는 docs/requirements.md이며, 사용자 시나리오·데이터 설계처럼 별도 산출물을 요청받으면 그 범위와 경로를 따릅니다. 기존 ID와 문서 구조를 가능한 한 유지합니다.
6. 대상 Issue 체크리스트와 문서의 요구사항·수용 기준을 연결하고, 포함 범위·제외 범위·의존 작업을 명시합니다. 요청받지 않은 후속 기능이나 전체 테스트 계획으로 확장하지 않습니다.

## Todo List에서 확인할 관계

대상 Issue에 관련된 항목만 확인합니다.

- CRUD: 항목 식별, 중복 내용, 입력 정규화, 수정 취소, 삭제 후 목록 및 순서.
- 완료·필터: 전체·진행 중·완료의 조건, 상태 전환 후 표시 결과, 숨겨진 항목의 보존.
- 입력·빈 상태: 허용 경계값, 잘못된 입력의 피드백, 전체가 비었을 때와 필터 결과가 없을 때의 구분.
- LocalStorage: 저장 대상, 재방문 복원, 읽기·쓰기 실패, 손상 데이터 및 사용자 동의 전 원본 보존. 키·스키마 상세는 요청 범위에 포함될 때만 설계합니다.
- 정책 간 충돌: 필터와 CRUD, 화면 상태와 영속 데이터, 저장 실패와 복원 결과를 함께 확인합니다.

## 검증과 보고

- 요구사항 ID 중복, 체크리스트 누락, 수용 기준 부재, 정책 충돌과 문서 링크를 확인합니다. 문서 변경에는 git diff --check를 적용합니다.
- 문서 작성·검토 완료와 기능 구현·실행 테스트 완료를 구분합니다. 문서에 수용 기준을 적었다는 이유로 기능 테스트를 통과 처리하지 않습니다.
- 확인된 근거만 완료 표시하며, 가정·미해결 질문·후속 검증을 결과에 남깁니다. GitHub 변경은 사용자 요청과 기존 권한 범위에서만 수행합니다.
- 결과에는 변경 문서, 체크리스트별 근거, 검증 결과와 미완료 사항을 포함합니다. 커밋·PR 작업이 요청되었으면 해당 결과도 보고합니다.
